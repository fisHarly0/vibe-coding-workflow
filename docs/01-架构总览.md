# 01 - 架构总览

## 设计立场

主流 Agent 框架（LangGraph、CrewAI、AutoGen 等）的核心抽象都是 **角色化多代理编排 + 状态图持久化**。本工作流沿用这一范式，但在 **个人开发者场景** 下做了针对性裁剪：

- 不引入额外编排框架，直接基于 Claude Code 原生 Subagent 能力实现
- 不假设企业级权限与监控基础设施，而是用 Markdown 文件作为持久化层
- 不追求完全自主，关键节点保留人类决策（半自主 / human-in-the-loop）

## 三层架构

```
┌─────────────────────────────────────────────────────────────┐
│  Layer 1: Orchestration (主对话 Supervisor)                 │
│  - 需求拆解、架构决策、子 Agent 调度                        │
│  - 关键决策节点保留人类确认                                 │
└─────────────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────▼───────────────────────────────┐
│  Layer 2: Specialized Sub-Agents (角色化执行)               │
│  - Explore       代码检索 / 知识发现                        │
│  - Plan          实现方案设计                               │
│  - Code Review   产出验证 / 反思                            │
│  - Security      批判性审计                                 │
│  - ultrareview   多 Agent 云端独立评审 (关键合并节点)       │
└─────────────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────▼───────────────────────────────┐
│  Layer 3: Persistent Memory (跨会话状态层)                  │
│  - MEMORY.md     用户偏好 + 项目档案 (粒度小、长期)         │
│  - HANDOFF.md    工程接续点 (粒度大、单项目)                │
│  - Auto Compact  Claude Code 原生上下文压缩                 │
└─────────────────────────────────────────────────────────────┘
```

## 角色与职责对照

| 角色 | 对应主流框架 | 在本工作流中的职责 |
|------|--------------|-------------------|
| Supervisor (主对话) | CrewAI Manager / LangGraph Root | 任务拆解、架构选型、节奏把控 |
| Explore | Researcher | 跨文件代码检索、外部知识调研 |
| Plan | Planner | 接到任务后输出分步实现方案 |
| Code Review | Verifier | 对产出做静态审计与回归思考 |
| Security | Critic | 安全敏感面（权限、注入、密钥）独立审视 |
| ultrareview | Multi-Agent Debate | 关键合并前的云端多 Agent 独立评审 |

## 与 ReAct / Plan-and-Solve 的对应

- **ReAct (Thought→Action→Observe)** 是基础循环，由 Supervisor 在每个回合执行
- **Plan-and-Solve** 由 Plan 子 Agent 接管，先全局规划再分步执行，避免短视
- **Reflection** 由 Code Review / Security 子 Agent 完成，对每轮产出做反思

详见 [03 - 工作流闭环](03-工作流闭环.md)。

## 为什么不用框架

LangGraph / CrewAI 适合团队级持续工程，但对个人开发者：

1. 引入运行时（Python 进程、消息队列）显著增加维护成本
2. 状态图改动需要代码部署，丧失对话即调整的灵活性
3. 角色定义最终仍要落到 prompt 上，框架不带来本质提升

本工作流选择 **直接利用 Claude Code 原生 Subagent + Markdown 持久化** 作为 "Poor Man's LangGraph"，在个人项目尺度下达到等价的工程效果，成本接近零。
