# 03 - 工作流闭环

## 三层迭代结构

每个真实任务都按下面的三层闭环展开：

```
┌─────────────────────────────────────────────────────────────────┐
│  Layer A — Plan-and-Solve (全局规划)                            │
│  Plan 子 Agent 输出分步计划，避免 ReAct 短视陷阱                │
└──────────────────────────────┬──────────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────────┐
│  Layer B — ReAct Loop (Thought → Action → Observe)              │
│  Supervisor 按计划逐步推进，每步调用工具并观察结果              │
└──────────────────────────────┬──────────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────────┐
│  Layer C — Reflection (反思)                                    │
│  Code Review / Security Review / 三层验证                       │
│  失败 → 回到 Layer B (再循环) 或 Layer A (重规划)               │
└─────────────────────────────────────────────────────────────────┘
```

## 三道自动校验

每次代码产出后强制经过：

1. **类型检查** —— TypeScript / mypy / Godot type hints，由 Agent 自主调用
2. **单元测试 / 编译** —— 项目本身的测试套件或编译器
3. **运行时实测** —— 启动开发服务、打开浏览器、跑实际功能流程

任何一层失败：

- Agent 自主分析 stack trace / 报错信息
- 决定 "局部修复" or "回到 Plan 重新设计"
- 不允许跳过校验直接报告 "完成"

## 关键节点的人类介入

这套工作流刻意保持 **半自主**，以下节点强制等待人类确认：

- **架构级决策** —— 选用哪个框架、是否引入新依赖
- **不可逆操作** —— `git push --force`、`rm -rf`、数据库迁移
- **公共可见动作** —— 提交 PR、发布到生产、群消息推送
- **预算变化** —— 新购服务、显著增加 token 消耗的策略

这与 2026 主流企业级 Agentic 实践的 "Autonomy Spectrum" 取向一致：从半自主到全自主是渐进过程，关键护栏不能省。

## 失败场景的复原路径

| 失败类型 | 处理路径 |
|----------|----------|
| 语法错误 | Layer C → Layer B 重试 |
| 测试失败 | Layer C → Layer B 局部修复 |
| 实测行为不符合预期 | Layer C → Layer A 重新规划 |
| 反复失败 (3 次) | 升级到人类，更新 HANDOFF.md 标记为 "阻塞" |
| 上下文窗口接近上限 | 写 HANDOFF.md → 开新会话 → 从 HANDOFF 接续 |

## 与 Self-Improvement 的距离

完全的递归自我改进（Recursive Self-Improvement）是 2028+ 的远期目标。本工作流在当前阶段已经具备的雏形：

- **prompt 自更新** —— Agent 在 MEMORY.md / CLAUDE.md 中累积反馈，下次自然采纳
- **工具自定义** —— 通过 MCP / 自定义 subagent 扩展能力，不必修改主模型
- **架构反思** —— 每次重大失败后会反向更新 HANDOFF.md 中的 "关键决策记录"

但仍处于 **"Agent 通过显式文件改善自己"** 的阶段，距离 "Agent 训练 Agent" 还有数年。这种克制的定位是有意的：在当前模型能力下，可解释性 > 自动化深度。
