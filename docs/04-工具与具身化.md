# 04 - 工具与具身化

## 立场

Agent 的能力上限不是模型本身决定的，而是它能**调用什么工具、操作什么环境**决定的。本章描述本工作流如何用工具协议把 Agent 接入真实开发环境，达到 "桌面端 Embodiment"。

## 工具栈分层

```
┌──────────────────────────────────────────────────────────┐
│  L0 — 模型原生工具 (Claude Code 内置)                    │
│  Read / Write / Edit / Bash / Grep / Glob / WebFetch     │
└──────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────┐
│  L1 — Subagent 编排工具                                  │
│  Agent (Explore / Plan / Code-Review / Security)         │
└──────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────┐
│  L2 — MCP (Model Context Protocol) 标准化扩展            │
│  filesystem / git / 浏览器 / 自定义业务工具              │
└──────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────┐
│  L3 — Computer Use / Embodiment                          │
│  直接操作终端、文件系统、浏览器、桌面应用                │
└──────────────────────────────────────────────────────────┘
```

## L2：MCP 标准化协议

MCP 是 2026 年 Agent 生态最重要的标准化协议之一。它的价值不是 "让 Agent 能调更多工具"，而是 **解决工具集成的版本碎片化问题**：

- 同一个 Agent 可以无缝接入不同来源的工具（官方、社区、自建）
- 工具升级不需要重写 Agent 端代码
- 可以把内部业务能力包装成 MCP server，让 Agent 直接调用

**典型接入：**

| MCP Server | 用途 |
|------------|------|
| filesystem | 跨项目文件批量操作 |
| git / github | 仓库状态查询、PR 操作 |
| 浏览器 | 自动化 UI 验证 |
| 自定义业务 | 把私有 API / 数据库包装成 Agent 可见工具 |

## L3：Computer Use 实战

Claude Code 本身就是 Computer Use 的最完整体现 —— 它在终端里、在文件系统里、在 git 工作树里直接执行操作。这种 **桌面端 Embodiment** 与传统 ChatBot 范式的根本区别：

| 维度 | ChatBot | 桌面端 Agent |
|------|---------|-------------|
| 输出形式 | 文本建议 | 直接修改文件 |
| 验证方式 | 用户复制粘贴 | Agent 自己运行测试 |
| 错误恢复 | 用户重新提问 | Agent 看到 stack trace 自动修复 |
| 工程闭环 | 不闭环 | 端到端闭环 |

## 数字-本地环境闭环示例

以 net-blog 上线流程为例：

```
意图: "把 blog 部署到 hlhaya.cn"
   │
   ├─ Plan Agent: 拆解为 [构建 → DNS → CDN → 证书 → 部署 → 验证]
   │
   ├─ Bash 工具: 执行 npm run build
   │   └─ 观察输出，发现构建失败
   │
   ├─ Reflection: 分析报错 → 定位到环境变量缺失
   │
   ├─ Edit 工具: 修复 .env.production
   │
   ├─ Bash 工具: 重新构建 → 部署
   │
   ├─ WebFetch 工具: 实测 hlhaya.cn 返回 200
   │
   └─ 写入 HANDOFF.md: "上线完成，存档结构待优化"
```

整个流程不需要用户在中间复制任何命令、粘贴任何输出。Agent 在自己的循环里完成 Thought → Action → Observe，这就是 Embodiment 的工程价值。

## 安全与护栏

桌面端 Embodiment 越强，护栏越关键：

- **路径白名单** —— Agent 默认只能读写当前工作树
- **敏感命令二次确认** —— `rm -rf` / `git push --force` / 数据库变更必须人类批准
- **密钥隔离** —— `.env` 类文件即使可读也禁止外发
- **可审计** —— 每次工具调用都记录在 HANDOFF.md 的 "本次会话动作清单"

这些护栏的核心思路是：**Embodiment 给 Agent 真实操作能力，但要让人类能在事后追溯每一步。**
