# 06 - 自我迭代机制（Recursive Self-Improvement Embryo）

> 完整的递归自我改进（Recursive Self-Improvement, RSI）是 2028+ 的远期目标，需要模型本身具备元认知与自训练能力。
> 本章描述的是当前模型能力下、个人项目尺度可立即落地的 **RSI 雏形**：让 Agent 改善 "下一次会话的自己"。

## 设计原则

1. **修改对象必须真实生效** —— 改 CLAUDE.md / MEMORY.md，下次新会话立刻读到，不是日志游戏。
2. **每一步可审计** —— 反思、模式、提案、批准都是 Markdown，git 追溯链完整。
3. **关键护栏不可省** —— Apply 之前必须人类批准，对齐 Autonomy Spectrum 的半自主立场。
4. **闭环必须能验证** —— 应用规则后，下次反思要能反向验证规则是否真的改善了行为。

## 六步闭环

```
   ┌──────────────────────────────────────────────┐
   │ 1. Observe                                   │
   │    任务结束追加 reflection-log.md            │
   └──────────────┬───────────────────────────────┘
                  │
   ┌──────────────▼───────────────────────────────┐
   │ 2. Reflect                                   │
   │    扫描近期反思 → patterns.md                │
   └──────────────┬───────────────────────────────┘
                  │
   ┌──────────────▼───────────────────────────────┐
   │ 3. Propose                                   │
   │    模式 → 具体改动建议 pending-updates.md    │
   └──────────────┬───────────────────────────────┘
                  │
   ┌──────────────▼───────────────────────────────┐
   │ 4. Approve  (Human-in-the-loop)              │
   │    人类逐条 ✅/❌ 标记                       │
   └──────────────┬───────────────────────────────┘
                  │
   ┌──────────────▼───────────────────────────────┐
   │ 5. Apply                                     │
   │    批准的条目合入 CLAUDE.md / MEMORY.md      │
   └──────────────┬───────────────────────────────┘
                  │
   ┌──────────────▼───────────────────────────────┐
   │ 6. Verify                                    │
   │    下次会话遵守新规则 → 新反思反向验证       │
   └──────────────┬───────────────────────────────┘
                  │
                  └─→ 回到 1（递归）
```

## 与 Reflection 子 Agent 的区别

第三章描述的 Reflection 是**单次任务内**的反思，作用于本轮代码产出。本章的自我迭代是**跨会话级**的反思，作用对象是 Agent 自己下次的行为约束。两者并行不冲突：

| 维度 | 任务内 Reflection | 跨会话自我迭代 |
|------|------------------|---------------|
| 触发 | 每次代码产出后 | 每次任务完成后 / 周期性 |
| 对象 | 本轮代码 | Agent 自身规则 |
| 持久化 | 修复代码 | 追加 reflection-log |
| 闭环长度 | 分钟级 | 天-周级 |

## 与论文中"自进化"的距离

主流文献中的 RSI 远比本机制激进 —— 包括模型自我训练、自动生成训练数据、Agent swarm 内部互训等。本机制仅做到：

- ✅ Agent 总结自己经验
- ✅ Agent 生成自我修改提案
- ✅ 修改后真实改变下次行为
- ❌ Agent 不修改模型权重
- ❌ Agent 不绕过人类批准
- ❌ Agent 不自动复制/分裂出新 Agent

把它定位为 "RSI 雏形" 是诚实的：闭环成立、机制完整，但故意保留人类决策权。这恰恰符合 Anthropic 等机构对 2026-2028 安全演进路径的判断 —— 在模型对齐能力到位前，自动化深度必须让位于可审计性。

## 实现位置

完整可运行的实现见仓库 [self-iteration/](../self-iteration/) 目录：

- `self-iteration/README.md` —— 系统总览
- `self-iteration/protocol.md` —— Agent 应当遵循的指令集
- `self-iteration/reflection-log.md` —— 反思日志（追加式）
- `self-iteration/patterns.md` —— 提炼出的模式
- `self-iteration/pending-updates.md` —— 待人类批准的更新提案

## 落地建议

不要一次启用全部六步。建议按以下顺序逐步引入：

1. **第 1 周**：只做第 1 步（Observe），让反思日志先积累 20 条以上原料
2. **第 2-3 周**：手动触发第 2-3 步，看 Agent 提炼模式的质量
3. **第 4 周**：开始走完整闭环，第一次 Apply 必须严格人类审核
4. **第 5 周后**：观察 Verify 阶段，看新规则是否真的改善了行为；不改善的规则要敢于撤销

启动得越慢，最终系统的稳定性越高。
