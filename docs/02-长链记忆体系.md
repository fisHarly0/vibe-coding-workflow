# 02 - 长链记忆体系

## 核心问题

LLM 的上下文窗口再大也是有限的。在持续数周、数十次会话的工程项目中，"上一次开会到哪了" 这件事不能依赖窗口本身。需要外置的、显式的、Agent 自己能读写的持久化层。

## 双层设计

```
                        ┌────────────────────┐
                        │   用户 (Human)     │
                        └──────────┬─────────┘
                                   │
            ┌──────────────────────┴─────────────────────┐
            │                                            │
   ┌────────▼─────────┐                       ┌──────────▼──────────┐
   │   MEMORY.md      │                       │    HANDOFF.md       │
   │ (用户级 / 长期)  │                       │ (项目级 / 接续点)   │
   ├──────────────────┤                       ├─────────────────────┤
   │ 偏好             │                       │ 当前进度            │
   │ 角色 / 背景      │                       │ 阻塞点              │
   │ 项目档案索引     │                       │ 下一步动作          │
   │ 工作风格反馈     │                       │ 关键决策记录        │
   │ 跨项目通用       │                       │ 单项目独占          │
   └──────────────────┘                       └─────────────────────┘
            │                                            │
            └──────────────────────┬─────────────────────┘
                                   │
                          ┌────────▼─────────┐
                          │   Claude Code    │
                          │  Auto Compaction │
                          └──────────────────┘
```

## MEMORY.md：用户级长期记忆

**特征：**

- 存放跨项目通用、变化缓慢的信息
- 由 Agent 在对话中主动读写，不需要用户手动维护
- 索引化结构：MEMORY.md 本身只是一行行的指针，详细内容拆到独立 .md 文件

**典型条目类型：**

| 类型 | 示例 |
|------|------|
| user | "用户是独立开发者，关注 AI 工程化落地" |
| feedback | "用户偏好简洁回复，不喜欢冗长总结" |
| project | "net-blog 已上线，存档在 状态档案.md" |
| reference | "外部文档在 Notion `工程文档` 中" |

完整模板见 [templates/MEMORY.md](../templates/MEMORY.md)。

## HANDOFF.md：项目级接续点

**特征：**

- 单项目独占，每个项目根目录一份
- 在每次会话结束 / 阻塞 / 切换前更新
- 内容是 "下一次开始时立刻能恢复工作所需的最小信息"

**结构骨架：**

```markdown
# HANDOFF — <项目名>

## 当前状态
<一句话描述项目当前所处阶段>

## 上次会话的产出
- ...
- ...

## 当前阻塞 / 待决策
- ...

## 下一步行动 (按优先级)
1. ...
2. ...

## 关键决策记录
- 2026-04-15  选择 Godot 4.x 而非 Unity，理由：...
- 2026-04-22  数据持久化用 JSON 而非 SQLite，理由：...

## 重要文件锚点
- `src/foo.gd` —— 主控制器
- `data/save.json` —— 存档结构
```

完整模板见 [templates/HANDOFF.md](../templates/HANDOFF.md)，脱敏示例见 [examples/handoff-godot-sample.md](../examples/handoff-godot-sample.md)。

## 与 Auto Compaction 的关系

Claude Code 内置的上下文自动压缩机制解决的是 **会话内长度问题**。MEMORY.md / HANDOFF.md 解决的是 **跨会话连续性问题**。两者互补：

- 会话内：自动压缩保留关键上下文
- 会话间：HANDOFF.md 承载工程接续点，MEMORY.md 承载用户/项目级稳定信息
- 新会话开始：Agent 读 MEMORY 与 HANDOFF，等价于 LangGraph 中加载 State

## 为什么这套做法有效

1. **可读、可审计** —— Markdown 让人类能直接验证 Agent 的记忆内容，避免黑盒
2. **零依赖** —— 不需要向量数据库、不需要专属服务，git 即版本控制
3. **可迁移** —— 项目搬到任何机器、任何 Agent 框架都能直接接续
4. **激励 Agent 主动维护** —— 文件本身就在工作目录里，Agent 每次会话都看见，自然会更新
