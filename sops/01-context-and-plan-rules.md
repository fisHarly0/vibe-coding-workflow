# 01 — Context 与 Plan 八条铁律

> 用 Claude Code / Codex 实现需求时，提了一大长串要求但成品像没改、或只做了简陋实现。**根因几乎都是 context 失控**（被自动 compact 掉、一次塞太多、或 thread 太长失忆）。下面 8 条是反复踩坑后凝出来的预防法则。

## 1. 绝不触发 compact，used 控制在 90% 以内

自动 compact 后大量细节会丢失。一旦 compact 过，Agent 对项目的"全面分析"就基于潜行记忆，**不是真实状态**。

- 默认目标：单 thread used 不过 90%
- 接近 80% 就开始考虑这个模块要不要分段做完后 `/clear`

## 2. 多用 plan mode，每次新改动先 `/clear`

按住 `shift` + `tab` 进 plan mode → 对齐需求 → 清空 thread 后选 `clear and implement`。每个新改动都先 `/clear` 拉新 thread。

不要在同一个长 thread 里连续做"调研 + 设计 + 实现 + 修 bug + 写测试 + 改文档"——分会话做，中间 `/clear` 隔离上下文。

## 3. 一次只改一个小点，30 分钟以上效果开始劣化

每个 thread 只改一个清晰小点，**不要试图一次塞 5 条不相关的要求**。等待时间过 30 分钟，Agent 开始"失忆写垃圾"；过 1 小时几乎是浪费时间。

- 单 thread 单一焦点
- 一旦感觉 Agent 开始绕、重复确认已确认过的事 → 立刻 `/clear`

## 4. 来源 / 参考 / 改动范围必须具体

不要靠 "你来决定" / "用最好的实现办法"。Agent 不会知道，必须给精确要求。**禁止以下空大需求**：

- 「优化屎山代码」
- 「减少性能开销」
- 「检查每一处代码」
- 「对所有源代码进行检查」
- 「全面审视架构」

这些都是空谈。具体到 "改 `lib/x.ts` 的 `funcA`，把 BigInt 累加改成 Number 转换前先 floor，理由是 ..." 才有用。

## 5. 不信任 AI 的"全面分析报告 / 项目评分"

不要相信 Agent 对项目的任何"全面"评分、"结构上升"报告。compact 之后这些全是潜行记忆，**多数是无依据虚假内容**。让它"改完获得更高评分"——纯自嗨。

如果非要让 Agent 给意见：
- 限定到一个具体文件 / 一段具体代码
- 要求引用 `file@line` 才算数
- 没有 `file@line` 的结论一律视为"想象"

## 6. 新项目不要让 Agent 一次全面实现

创建新项目 plan mode 几乎都会让你选阶段性实现。`recommend` 是默认正解，其它选项相当于"上中下策"——看起来更全面但通常意味着大块复写或工作量翻倍。

**勘误**：选项 detail 里明写 "不推荐 / 大块复写" 才避开。工作量与 `recommend` 相当的可以选。

## 7. spec 切小模块顺序开发，比纯 plan mode 更稳

`spec`（步骤准备文档）是社区总结出来的实践：先通过对话建出开发框架（txt/md），你和 Agent 来回补充对齐。然后**把全局拆成多个小模块文档**，让 Agent 逐个开发。

- 形成的 spec **禁止让 Agent 再去改**（加 `AGENT.md` 约束）
- spec 小文档不够小一样会引发上下文惨案——目标是单模块用一个会话能写完
- 比纯 plan mode 稳，因为 plan 最后的"开发计划"本身也是一种 compact

## 8. AGENT.md 失效的两个真因 + 标准开场

`AGENT.md` 是最高优先级的项目级行为约束文件，但偶尔失效。两个常见根因：

1. 输入未明确 `cd` 到本地仓库路径（用 "对本地 XX 项目进行操作" 的说法）
2. 直接使用云端代码仓地址——会拐个弯回到本地但也会无视 AGENT.md

**标准开场**：

```
cd <绝对路径>，遵从 AGENT.md。
本次任务：<具体描述>
```

`cd` 写绝对路径而非相对路径，是为了让 Agent 落到一个明确的工作树根，AGENT.md 才会被加载并生效。

## 不要做什么（反向清单）

- 让 used 越过 90%（下一轮回复就会 compact 把细节磨没）
- 一个 turn 内连续追加 5 条不相关修改
- 单 thread 用超 30 分钟还不 `/clear`
- 提"全面优化 / 全部检查 / 你看着办"这类空大需求
- 信 Agent 给出的"项目结构评分上升"
- plan mode 选项挑"看起来更全面"但非 `recommend` 的（除非 detail 工作量与 `recommend` 相当）
- 让 Agent 自己更新 spec 文档（spec 与 AGENT.md 只由人改）
- 不 `cd` 到本地仓就开始干，或丢一个云端仓地址过去
