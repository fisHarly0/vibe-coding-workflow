# 03 — 打开新会话的决策树（A / B / C）

> 每次新开一个 Claude / Codex 会话之前，先回答一个问题：**这次要干什么？** 不同场景拖不同的文件、说不同的第一条话。

## 决策树

```
┌─ 1. 开全新项目（还没代码）         → A
├─ 2. 继续已有项目（写下一个模块）   → B
└─ 3. 临时小任务（不归任何项目）     → C
```

---

## A 场景 · 开全新项目

### 拖入

| 文件 | 必/选 |
|------|-------|
| [01 Context 与 Plan 八条铁律](01-context-and-plan-rules.md) | 必 |
| [templates/HANDOFF.md](../templates/HANDOFF.md) | 必（接续骨架） |
| 项目想法草稿（txt / md，任意格式） | 选 |

### 第一条消息（直接抄）

```
我要做一个 XX 项目。
- 目标：...
- 技术栈倾向：...（或写"由你建议"）
- 部署：...（或写"暂不部署"）
- 工期感觉：...

不要直接写代码。按下面顺序：
1. 进 plan mode（我会按 shift+tab）
2. 先问我必要的澄清问题（一次问完，别一来一回）
3. 给我一份 spec（txt 格式），把项目切成 N 个能独立开发的小模块，
   每个模块标注：
   - 预估工作量 + 依赖关系
   - acceptance criteria（什么算 done，具体到接口契约 /
     边界条件 / 错误码 / UI 验收点，避免"差不多了"歧义）
4. 给我一份 AGENT.md 草稿，约束以后会话只能改指定模块，
   不要乱改其他文件 + 不要自己改 spec
5. 初始化接续文档：
   - 小项目 → 项目根建 HANDOFF.md（按 templates/HANDOFF.md 模板）
   - 预计 10+ 次会话的中长线项目 → 建 <项目名>-档案/ 目录，
     初始化必备两件（状态档案.md + vibe库资料.md），并加进 .gitignore

我已经读过 context 法则，不要重复展开。
```

### 这次产出

- `specs/` 目录，里面切好的多份小 spec
- 项目根 `AGENT.md` 草稿
- 接续文档：`HANDOFF.md` 或 `<项目名>-档案/` 必备两件（五件套规范见 [07](07-project-archive-five-piece.md)）

### 这次**不**做的事

- 写实际代码
- `npm init` / `git init` / 装依赖（让用户自己确认目录后再做）
- 把整份 spec 塞进一份大文档（spec 不够小一样会引发上下文惨案）

## B 场景 · 继续已有项目（最常用）

### Step 0：先看项目用的是哪种接续形态

1. **档案目录里有 `README.md`** → 分层档案（大项目）。**先拖 README**，按里面"做 X 类任务拖哪几份"的表选具体子档案，不拖全家桶
2. **有 `<项目名>-档案/` 但无 README** → 五件套平铺。按下表拖
3. **只有 `HANDOFF.md`** → 轻量形态。拖 HANDOFF + 当前模块 spec + AGENT.md

**识别 stub**：有的 `状态档案.md` 已 stub 化（<2KB / 顶部明示"已升级为 README"）——按 stub 里的指路拖，别把 stub 当真档案用。

### 拖入（**只**拖必要，不拖大目录）

| 文件 | 必/选 |
|------|-------|
| `状态档案.md`（或 `HANDOFF.md`） | 必（onboarding 真源） |
| `最新日志.md` | 必（如果存在） |
| spec 里**当前要做的那一个模块** | 必 |
| 项目根 `AGENT.md` | 必 |
| `最新自审.md` | 选（本次要修自审遗留问题才拖） |

### 第一条消息（直接抄）

```
cd D:\path\to\项目根，遵从 AGENT.md。
本次只做 spec 模块 N：<标题>。

进 plan mode 对齐 → 选 plan 选项默认 recommend → 写完跑最小测试。

用 /clear 而不是堆 thread，used 别过 90%。
```

### 期间规则

- 单 thread 不超 **30 分钟**，过了就停下 `/clear` 重开
- 一次只改一点，**不**接"顺手把 X、Y、Z 都改了"
- Agent 给"全面分析报告 / 项目结构评分上升了"这种 → **不信**
- 卡住 → `/clear` 重开，**不**继续硬聊
- plan mode 选项默认 `recommend`，除非 detail 明写"不推荐 / 大块复写"才避开

### 结束动作

按 [02 五段式 lifecycle 的 finishing + learning](02-five-phase-lifecycle.md#4️⃣-finishing没过不准-learning没过不准-clear) 跑：

- 改写接续文档（状态档案 / HANDOFF）的"当前状态 / 下一步行动 / 关键决策"
- 五件套项目：写日志 + 双写 `最新日志.md`
- 档案有写入且建了经验仓 → **直接回送四件套 + 告知**（[08](08-experience-repo-and-writeback.md)），不再问
- 出现跨项目新经验 → Agent **主动问**："要不要沉淀进 MEMORY.md / CLAUDE.md？" → 拍板 yes/no

## C 场景 · 临时小任务

### 拖入

任务相关的最小文件集即可。

### 第一条消息

直接描述任务，**不需要**项目档案系统。

> 例外：如果做着做着发现要写代码 + 持续多个 turn → 升级成 B（中途接入 HANDOFF.md）。

---

## 三件事每次都记

| 项 | 动作 |
|----|------|
| **used** | 控制 90% 以内，过了就 `/clear` 重开 |
| **大动作前** | `shift+tab` 进 plan mode 对齐 |
| **收尾** | 档案有写入 → Agent 直接回送 + 告知；出现新经验 → Agent 主动问、用户拍板 |

---

## 不要做什么

- 把项目下的所有 md 都拖给 Agent（撑爆 context）
- B 场景不拖接续文档（状态档案 / HANDOFF）就开干（Agent 不知当前在哪）
- 分层档案项目跳过 README 直接拖子档案（容易拖错版本）
- 把 stub 化的状态档案当真档案用（按 stub 指路走）
- A 场景一上来就说"帮我做一个 XX 项目"（无 spec 直接全面实现的死路）
- 单 thread 写 2 个模块（分两次会话，中间 `/clear`）
- 让 Agent 自动改 spec 或 AGENT.md（这两个文件**只**由用户改）
- 收尾静默跳过沉淀（例行回送直接做+告知；新经验要开口问；没东西就明说）
